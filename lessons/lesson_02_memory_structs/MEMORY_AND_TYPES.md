# Робота з пам'яттю та типами даних: C++ vs Rust (ESP32)

## 1. Переповнення цілих чисел (Integer Overflow)

Аналізуємо приклад:
```cpp
uint8_t a = 200;
uint8_t b = 100;
uint8_t sum = a + b;
```

У результаті `sum` дорівнює **`44`**.

### Як це працює у C++
1. `uint8_t` обмежується діапазоном 0..255 ($2^8 = 256$ значень).
2. При виконанні `a + b` відбувається цілочисельне підвищення (Integer Promotion) до `int` (32 біти на ESP32), тому проміжне значення = `300`.
3. При записі назад у `uint8_t` старші біти відсікаються: $300 \pmod{256} = 44$.
4. C++ виконує це мовчки, не викликаючи жодних помилок чи попереджень під час виконання.

### Як це працює у Rust
В аналогічному коді на Rust:
```rust
let a: u8 = 200;
let b: u8 = 100;
let sum = a + b;
```
- **Debug:** програма впаде з `panic!` (захист від неочікуваної втрати даних).
- **Release:** відбудеться відсікання до `44`.

Якщо переповнення є очікуваною поведінкою, у Rust це вказують явно:
- `a.wrapping_add(b)` — поверне `44` у будь-якому режимі.
- `a.saturating_add(b)` — поверне `255` (верхня межа `u8`).
- `a.checked_add(b)` — поверне `Option::None`.

## 2. Області пам'яті в ESP32

```
+-------------------------------------------------------+
| Flash (.text / .rodata) — прошивка та константи       |
+-------------------------------------------------------+
| SRAM (.data / .bss) — глобальні змінні                |
+-------------------------------------------------------+
| Heap — динамічна пам'ять (malloc / new)               |
|                                                       |
| Stack — локальні змінні функцій                       |
+-------------------------------------------------------+
```

### Стек (Stack)
Швидка пам'ять для локальних змінних та викликів функцій. Звільняється автоматично при виході з функції.
- **Ризик:** при глибокій рекурсії або великих локальних масивах виникає Stack Overflow, що викликає перезавантаження мікроконтролера.

### Купа (Heap)
Динамічна пам'ять (`malloc`, `new`, `String`).
- **C++:** пам'ять виділяється під час виконання. Потрібно контролювати вільний обсяг (`ESP.getFreeHeap()`), оскільки часті реалокації створюють фрагментацію та витоки (memory leaks).
- **Rust (`no_std`):** купа за замовчуванням не використовується. Змінні живуть на стеку або у статичній пам'яті, що виключає витоки пам'яті на рівні компілятора.

### Глобальні змінні (.data / .bss)
- `.data` — глобальні змінні з початковим значенням.
- `.bss` — глобальні змінні, ініціалізовані нулем.
Існують увесь час роботи програми.

### Flash-пам'ять (.text / .rodata)
Енергонезалежна пам'ять, де зберігається виконаний код прошивки та константні рядки (`PROGMEM`).

## 3. Коротке порівняння

| Параметр | C++ (Arduino) | Rust (`no_std`) |
|---|---|---|
| **Overflow** | Мовчки відсікає ($300 \to 44$) | Panic у Debug, явні методи (`wrapping_add`) |
| **Heap** | Динамічний (`malloc`/`new`), ризик leaks | Не використовується за замовчуванням |
| **Перевірка Heap** | Ручна через `ESP.getFreeHeap()` | Гарантія компілятора |
